# genparser roadmap — phase status

The development plan for taking `genparser` from working prototype to a
well-rounded, distributable language server. Eight phases; each is either
**done** (with what was actually implemented) or **planned** (with what it is
meant to implement). Phases are executed in order, but Phase 5 (schema
scale-out) is a continuous workstream that runs alongside everything after
Phase 2.

| Phase | Title | Status |
|---|---|---|

| 1 | Server data-path hygiene | ✅ done (2026-06-10) |

## Phase 0 — Measure first ✅

**Goal:** numbers that gate the incremental-reparse design; obtain the real
game-data corpus. Full report: [`phase0-baseline.md`](phase0-baseline.md).

**Implemented:**

- Criterion benchmarks: `crates/syntax/benches/parse.rs` (tokenize, full
  parse) and `crates/analysis/benches/analyze.rs` (diagnose, semantic tokens,
  definitions, keystroke path) over synthetic 1k/10k/50k-line INI.
- Corpus fetch scripts `scripts/fetch-corpus.ps1` / `.sh`: sparse shallow
  clone of `TheSuperHackers/GeneralsGamePatch2` `GeneralsZH/Data/INI` into
  the gitignored `corpus/` (135 files).
- Dialect check: zero `#`-preprocessor lines in the corpus — it is the plain
  engine dialect, no flattening needed. All 135 files decode as UTF-8.
- Smoke pass: zero panics; timings and a diagnostic-code histogram recorded.

**Key outputs:** per-keystroke budget set at **≤ 10 ms p95** for
parse + diagnose + publish. Largest real file `ParticleSystem.ini` (61,719
lines) cost 37 ms per keystroke — 3.7× over budget — plus ~50 ms per
`semanticTokens/full` repaint, producing a **GO verdict for all three parts
of Phase 3** (block splice, per-block analysis cache, range tokens).

## Phase 1 — Server data-path hygiene ✅

**Goal:** stop shipping the whole document per keystroke and stop re-parsing
per request — pure wins independent of parser speed.

**Implemented:**

- `TextDocumentSyncKind::INCREMENTAL`: `didChange` deltas are applied to the
  document rope via `convert::apply_change` (full-replacement `range: None`
  still handled).
- `DocumentState { rope, parse, version }` per open document: one parse per
  change batch; completion/hover/definition/semanticTokens reuse the cached
  parse — zero reparses on read-only requests.
- Position-encoding negotiation at `initialize`: UTF-8 when the client
  offers it, otherwise true UTF-16 code-unit columns (`convert.rs` rewritten
  encoding-aware; previously Unicode-scalar columns, an off-by-N on
  non-ASCII lines).
- Version-stamped diagnostics with a stale-drop guard (superseded work is
  not published).
- Lossy (non-UTF-8-tolerant) disk reads in `scan_workspace`/`rope_for`.

**Verified by:** extended `crates/server/tests/e2e.py` (incremental deltas
vs full-text baselines, CRLF, EOF edits, version stamps) and a property test
in `convert.rs` replaying random LSP delta sequences against a string
reference in both encodings.

## Phase 2 — Corpus harness as a permanent gate ✅

**Goal:** turn the smoke pass into a regression gate and a triage tool that
validates the parser/oracle and produces the schema backlog.

**Implemented:**

- `crates/analysis/tests/corpus.rs` (`#[ignore]`-gated): two passes (index
  all definitions, then timed parse + diagnose per file), printing a
  diagnostic histogram, top messages, and per-hit detail lines. Asserts
  **zero panics, zero `syntax`, zero `unknown-block`** across all 135 real
  files.
- Schema grew **5 → 63 blocks**: every entry of the engine's top-level
  dispatch table (`INI.cpp` `theTypeTable`) has at least a structural
  skeleton (generated by `scripts/add_skeleton_blocks.py`, sub-structure
  hand-checked against engine parse functions).
- New schema concepts in `crates/schema`: recursive, context-keyed
  `sub_blocks` (resolves keywords that are a block in one context and a
  field in another, e.g. `ParticleSystem`) and `terminated: false` for
  single-line directives (`BenchProfile`, `ReallyLowMHz`, `LODPreset`),
  parsed as file-scope fields via the new `OpenerOracle::opens_at_file_scope`.
- `CURATED_SUBBLOCKS` extended (UnitSpecificFX/Sound, decal templates) for
  keywords that appear inside module scopes.
- `ButtonSet` identified as a GeneralsGamePatch2 community-patch addition
  (absent from the retail engine) and added as such.
- Spec pair `StructureTest.{ini,spec.toml}` pins all of the above.

**Key outputs:** syntax diagnostics 945 → 0, unknown-block 18,348 → 0. The
remaining warnings are the quantified Phase 5 backlog: ~17.7k
`unknown-field`, ~12.1k `unknown-module`, 73 `unresolved-reference`.

## Phase 3 — Incremental reparse + incremental analysis ✅

**Goal:** keystroke cost proportional to the edited block, not the file
(hard project requirement). Full report:
[`phase3-incremental.md`](phase3-incremental.md).

**Implemented:**

- **Block-splice incremental reparse** (`crates/syntax/src/incremental.rs`,
  exposed as `Analyzer::reparse`): the edited top-level children of ROOT
  (widened one sibling, extended to line boundaries) are reparsed as a
  fragment and spliced into the old green tree; unchanged blocks keep
  pointer-identical green nodes. Exact by construction — the scope stack is
  empty at every top-level boundary and the lexer is line-local. Falls back
  to a full parse (observable as `Strategy::Full`) when the fragment ends
  with an open scope while text follows, e.g. a deleted `End`.
- **Per-block diagnostics cache** (`diagnostics::DiagnosticsCache`,
  `diagnose_with_cache`): keyed on green-node pointer identity (entries keep
  the `GreenNode` alive, so keys can't be reused), spans stored
  block-relative; invalidated by `WorkspaceIndex::generation()`, which bumps
  only when a file's definition *names* change, so ordinary keystrokes keep
  the cache warm.
- **`semanticTokens/range`**: block-granular viewport tokens
  (`semantic::semantic_tokens_range`); the server advertises `range: true`.
- **Server keystroke path**: `did_change` applies each delta to the rope and
  keeps the parse in lockstep via incremental reparse (`DocumentState` gains
  `text: Arc<str>` + diagnostics cache); `refresh` only diagnoses (cached)
  and publishes.

**Verified by:** equivalence fuzzing at three layers — every spliced result
compared against a fresh full parse (text, tree structure, errors,
diagnostics, cached diagnostics): 2,400 chained random edits in the syntax
crate (97% spliced), real-oracle sequences over all spec INIs plus all 135
corpus files (1,080 edits, 96% spliced), and wire-level e2e cases including
an `End`-deletion fallback.

**Key outputs:** keystroke on ParticleSystem.ini (61,719 lines)
**44 ms → 147 µs** (~300×); synthetic 50k lines 35.1 ms → 283 µs; viewport
semantic tokens 173 µs vs ~50 ms full. Budget met with ~70× headroom.

## Phase 4 — Value-type validation completion ✅

**Goal:** implement the per-token value validators still stubbed out in
`diagnostics.rs`, clearing all 6 `xfail` assertions in
`ArmorTest.spec.toml` / `ObjectTest.spec.toml`.

**Implemented:**

- **`ValueType::TokenList { tokens }`** (schema `format_version` 2): a fixed
  sequence of individually-typed tokens, used for Armor coefficients
  (`Armor = <DamageType|Default> <percent>`, Armor.cpp
  `parseArmorCoefficients`) and WeaponSet's `Weapon = <slot> <weapon ref>`.
  Diagnostics validate each position; completion offers the element at the
  cursor's token index; semantic tokens classify per element.
- **Sub-block field schemas**: `ScopeSchema::SubBlock` — a `MODULE` node
  with no module name now resolves against the enclosing scope's declared
  `sub_blocks`, so sub-block fields validate and complete. Populated from
  the engine: `Object`/`ObjectReskin` → `WeaponSet` (Conditions/Weapon/
  AutoChooseSources/PreferredAgainst/ShareWeaponReloadTime/
  WeaponLockSharedAcrossSets) and `ArmorSet` (Conditions/Armor/DamageFX);
  `FXList` → `Tracer` nugget (fully typed incl. a Color field);
  `MultiplayerColor` block fully typed; `Weapon.ScatterTarget` (Coord2D).
  New value sets: `armor_damage_type` (damage types + `Default`),
  `weapon_slot`, `weapon_set_conditions`, `armor_set_conditions` — all
  transcribed from the engine name tables.
- **Validators** (engine-faithful): Color `R:<int> G:<int> B:<int> [A:<int>]`
  with 0–255 range, tags in order, case-insensitive, `:`-separated
  (`parseRGBColor`/`parseColorInt`); Coord2D/3D `X: Y: [Z:]` reals;
  Percent now *requires* the `%` sign (stricter than the engine's bare
  `scanReal` — `Armor = X 2` almost never means 2%). New codes:
  `bad-color`, `bad-coord`.
- **Structure warnings**: `missing-module-tag` (ThingTemplate.cpp requires a
  tag per module) and `missing-condition` (a WeaponSet without `Conditions`
  silently becomes the default set; real game data omits it in only 5 of
  862 WeaponSets — not warned for ArmorSet, where omission is idiomatic at
  118 of 1,382).
- Fixed a latent `ast::Module` bug exposed by the tag check: header-argument
  scanning ran past the header line, reading the closing `End` as the
  module name/tag.

**Verified by:** all 6 xfail flags dropped (harness-forced); new spec pairs
`ColorTest`, `CoordTest`, `DurationTest`, `ValueGoodTest` (every validator's
good values under `no_errors`); corpus re-run: **zero new error-severity
diagnostics** across all 135 real files, `missing-condition` hit exactly the
5 predicted WeaponSets, unknown-field dropped by 56 from the newly typed
scopes.

## Phase 5 — Schema scale-out 🔲 (continuous)

**Goal:** drive the corpus warning backlog (~17.7k `unknown-field`, ~12.1k
`unknown-module`) toward zero, in corpus-frequency order.

**Planned:**

- Backlog order from the corpus histogram: Object fields first
  (EditorSorting ~1.7k, Shadow, the Geometry* family, RadarPriority,
  Voice*), then the module long tail (SlowDeathBehavior ~1.4k, FXListDie
  ~1.1k, FlammableUpdate, DestroyDie, TransitionDamageFX, PhysicsBehavior,
  CreateObjectDie, AIUpdateInterface), then Weapon fields
  (DelayBetweenShots, RadiusDamageAffects).
- Per-block checklist (codifies the CLAUDE.md workflow): find the
  `FieldParse` table in `GeneralsCode/` → translate entries to `ValueType`
  (lenient `Unknown { parse_fn }` when unclear) → `defines`/RefKind +
  module_slots → spec pair → schema + spec tests → corpus confirms that
  block's unknown hits drop to ~0.
- A coverage report (script or `#[ignore]` test) diffing engine `FieldParse`
  tables against schema entries, giving one tracked number for the README.
- Split `schema.json` per-domain only when its size actually hurts.

**Milestones:** M1 zero `unknown-block` corpus hits (already reached in
Phase 2) → M2 top-20 blocks fully field-typed with value sets → M3 module
long tail below an agreed `unknown-field` threshold.

## Phase 6 — LSP breadth 🔲

**Goal:** round out the feature set, ordered by value/cost.

**Planned:**

1. Cheap wins off existing structures: `documentSymbol`, `foldingRange`
   (block spans), `workspace/symbol` (off the existing `WorkspaceIndex`).
2. `references` (extend `index.rs` with per-file reference *sites*; today it
   stores definitions only); `rename` falls out as index-backed edits.
3. `semanticTokens` delta; make `scan_workspace` async/background (currently
   synchronous in `initialized`, which hurts on full-mod folders).
4. Last: formatting (indent normalizer over the lossless CST) and code
   actions (insert missing `End`, did-you-mean for enum members).

Each feature lands spec-first for the analysis layer plus an `e2e.py`
assertion for the wire handler. Before this phase: reassess the pinned,
archived tower-lsp 0.20 against forks (`tower-lsp-server`, `async-lsp`).

## Phase 7 — Distribution 🔲

**Goal:** installable by modders without a Rust toolchain.

**Planned:**

- CI matrix (win-x64, linux-x64, mac-x64/arm64) → GitHub Releases with
  checksums, tag-triggered.
- VS Code: platform-specific `.vsix` via `vsce package --target` with the
  bundled binary (config-path override kept); publish to the Marketplace and
  OpenVSX (GPL-3.0 is Marketplace-compatible).
- README config blocks for Neovim / Helix / Zed.

**Exit criteria:** a clean-machine Marketplace install gives diagnostics on
a ZH INI; the release pipeline is reproducible from a tag.
